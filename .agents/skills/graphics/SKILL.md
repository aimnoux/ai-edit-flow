# Graphics in code

Every chapter is a composition `engine/<slug>-ch<N>.html` generated by `build.py` from `template.html`;
your code is the scene `engine/scenes/<slug>/ch<N>.js`. The look comes from `style/` (tokens, world,
overlay).

## HyperFrames rules

- One root timeline, paused: `TL` in `kit.js`, registered by `finish.js`. Nested scene timelines
  are not paused.
- Every visible layer has `data-start` and `data-duration` (`class="clip"`); the template does this
  for the four layers (world, stage, hud, overlay), scenes live inside `#stage`.
- No CSS transitions. Changing numbers are prepared values set with `TL.set` (`countUp`): frames
  render out of order.
- Videos inside a composition are `muted`; sound is mixed outside (`sound`).
- Docs: `node engine/hf.mjs docs <topic>` or https://hyperframes.heygen.com/llms.txt.
- Container overflow of `.line` masks is marked as intended by the kit.

## Timing by words (`kit.js`)

```
W("2.3", "the distance")      second a phrase starts in block 2.3;  WE(...) when it ends
TR("2.3", "trick")            a trigger word of the script ([trick])
B("2.3")                      { s, e } of a block;  P("2.3", 1)  paragraph 1
CHAPTER                       { num, title, index, count };  D  duration of the composition
```

Phrases are matched by prefix, so inflections don't matter. If the speech drifted from the script, the
time is estimated from the position in the paragraph and logged in `window.EST`: check those in the
preview. Never type a second by hand when a word can give it.

## Building blocks

```
scene(s, e, { enter: "fade|zoom|punch|rise|cut", exit: "fade|up|cut" })   cut(s, e)
rich(parent, "A [word] in brackets is an accent", "h1", { left, top })   -> { box, words, acc }
reveal(r.words, t)  hideUp(r.words, t)  follow(r, "2.3", "first words")   lines from under a mask, or word by word with the voice
glow(node, t, { box: true })  accents(r, [t1, t2])                          one lit element at a time (style's --glow)
list(parent, items, times, { x, y, w })                                    numbered list, previous item dims
chapterTitle(s, e, name, sub)  progress(s, e)                              title card and the progress bar
stampIn(node, t)  wipe(node, t)  lineIn(node, t)                            appearances inside a thing: not everything fades
typeText(node, text, t0, t1)  typeText(..., { stream: true })             typed input / an AI answer arriving in bursts
countUp(node, from, to, t, dur, fmt)                                        a number through prepared values
camTo(sc, t, scale, px, py, cx, cy, dur)  camSet(...)                      the camera inside a scene: to what is being read
el(tag, cls, parent, html)  svg(tag, attrs, parent)  at(e, x, y, w, h)     DOM helpers;  sfx(name, t, vol)  a sound cue
measure(sc, fn)  measureIn(host, node)                                      layout of hidden scenes
```

Structural classes: `.hero .h1 .h2 .body .dim .mono .card .pill .tag .marker .strike .line .in .acc-text`.
Sizes and colors are tokens (`var(--fs-h1)`, `var(--acc)`); never a literal color in a scene unless the
thing itself has it (a product's button, a brand's logo).

## What a frame must do

- **Something new every 1.5-3 s** in 16:9: a thing enters, the camera moves to what is spoken, a line
  appears, a value changes. A frame with nothing happening for 3 s is a finding in review.
- **Text in the frame is a term, a number, a name, a scheme**, not the sentence being spoken.
  A line stays at least 0.5 s + 0.3 s per word.
- **One focus**: the main thing is at least 40 % of the frame's height or width; one element lit.
- **Appearances have a reason**: typed text types, a stamp lands, a number opens; the only effect that
  is a fade is a scene change. Exits are shorter than entries (0.35-0.5 s) and never a hard click.
- **No defaults**: no bouncing eases, no pulsing loops, no camera drift, no glow for decoration,
  no gradient text, no emoji for icons. The reviewer checks the full list separately.
- The climax (an answer, a number, a reveal) lands on its word and holds at least 1 s.
- Things from the person's world (a document, a chat, a phone) are built once, as a function in
  `engine/scenes/<slug>/things.js` or in `style/`, and reused; a thing looks like the real product.

## Working loop

1. Read the chapter's text and triggers in `videos/<slug>/script.md`; list the beats: what appears
   on which word.
2. Write the scene, then `python engine/verify.py <slug>-ch<N>` for checks and cached review sheets.
   For a targeted snapshot use `python engine/shots.py <slug>-ch<N> <seconds...>`. Preview if needed:
   `.claude/launch.json` → `engine`, `http://127.0.0.1:8790/<slug>-ch<N>.html#t=12.5`.
3. `review` before showing. Fix P0, then P1. Then the person sees the sheet or a draft render.
4. A correction from the person about the look → `style/visual.md` (through `style`), not only the scene.
